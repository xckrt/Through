# Tropa: архитектура

Цель: человек ставит программу, нажимает одну кнопку, и YouTube с Discord работают.
Дальше программа сама замечает, что провайдер что-то поменял, и чинит.
Без батников, без «попробуй general_alt3».

## Компоненты

```
┌──────────────────────┐   named pipe    ┌─────────────────────────────┐
│  Tropa.Tray (WPF)    │ ◄─────────────► │  Tropa.Service (LocalSystem)│
│  иконка, статус,     │   JSON-RPC      │                             │
│  кнопки, уведомления │                 │  Watchdog ──► Prober        │
└──────────────────────┘                 │      │          ▲           │
                                         │      ▼          │           │
                                         │  Tuner ─────────┘           │
                                         │      │                      │
                                         │      ▼                      │
                                         │  EngineHost ──► winws.exe   │
                                         │  Fetcher (релизы bol-van)   │
                                         └─────────────────────────────┘
                     Tropa.Core: Prober, Tuner, модели — без Windows-зависимостей
```

| Модуль | Что делает | Статус |
|---|---|---|
| **Prober** | Проверяет сервис по этапам DNS → TCP → TLS → HTTP → передача и называет способ блокировки | ✅ готов, 17 тестов |
| **Tuner** | Перебирает стратегии `winws`, на каждой гоняет Prober, выбирает лучшую на сервис | ✅ готов с фейковым движком, 10 тестов |
| **EngineHost** | Запуск и остановка `winws.exe` с нужными аргументами, сбор его stderr | ✅ `Tropa.Engine/WinwsEngineHost`, проверен на фейковом winws |
| **Fetcher** | Скачивает zapret из официальных релизов, сверяет SHA-256 | ✅ `Tropa.Core/Engine`; закреплён v72.13: хеш архива и хеш `winws.exe` |
| **Watchdog** | Раз в N минут лёгкий Prober; при деградации запускает Tuner | ✅ в `TropaController`: перезапуск упавшего winws, переподбор после 2 провалов подряд |
| **Service** | Windows-служба: держит всё выше, переживает перезагрузку | ✅ `Tropa.Service` (install/uninstall/run); логика в Core `Control/` |
| **Tray** | UI. Без прав администратора, только говорит со службой | ✅ своя рамка, вкладки «Обзор / Приложения / Журнал / Настройки», значок в трее |

## Почему Prober устроен по этапам

При провале TLS пробник открывает второе соединение на тот же IP с нейтральным SNI
(`ProbeOptions.NeutralSni`, по умолчанию `ya.ru`). Если сервер ответил, режут по имени (`SniFiltered=true`),
если нет, глушат весь TLS на адресе (`false`).


«Не открывается» ничего не говорит. Этап и способ провала сразу сужают поиск стратегии:

| Что видим | Что это значит | Что пробовать |
|---|---|---|
| `DnsBogus` | провайдер подменяет DNS | DoH/DoT, а не winws |
| `TcpTimeout` / `TcpRefused` | блок по IP | winws не поможет, нужен туннель |
| `TlsReset` | RST сразу после ClientHello, фильтр по SNI | `fake`, `split`, `disorder` по SNI |
| `TlsTimeout` | ClientHello дропается молча | то же, плюс `fake` с низким TTL |
| `TlsReset`/`TlsTimeout` + `SniFiltered=false` | на нейтральный SNI тот же IP тоже молчит: глушат TLS на адресе | winws вряд ли поможет, нужен туннель |
| `TransferStalled` в окне 8–32 КБ | «заморозка 16 КБ» ТСПУ | `fake` + десинхронизация на весь поток |
| `Slow` | шейпинг | стратегии против замедления (googlevideo) |
| `HttpBlockPage` | заглушка (451 / редирект) | DoH + десинхронизация |

Отсюда главная фишка Tuner: он перебирает не все 40 пресетов вслепую, а сначала те, что лечат
конкретный диагноз. Это быстрее и честнее объяснимо пользователю.

## Tuner

Код в `src/Tropa.Core/Tuning`, пресеты в `src/Tropa.Cli/presets.json`.

```
diagnosis = Prober по выбранным сервисам без обхода
if контрольные лежат: стоп (нет сети)
для каждого сервиса:
    уже Ok                                      → AlreadyOk
    все провалы по адресу (Tcp*, SniFiltered=false) → NotTreatable, нужен туннель
    candidates = presets.Where(p => p.Treats ∩ диагнозы).OrderBy(p => p.Cost)
    for each candidate:
        session = IEngineHost.Start(пресет, хосты и порты сервиса)
        2 прогона Prober (без проверки нейтральным SNI), по каждой цели худший
        session.Dispose()                     // и при исключении, и при отмене
        оценка лучше прежней лучшей → запомнить (при равенстве остаётся более дешёвый)
        все цели Ok: досрочный выход
TuningProfile.Apply(report) → profile.json   // только сервисы, где нашёлся пресет
```

Оценка (`TuneScore`): число Ok, потом Throttled, потом сумма «докуда дошли» упавшие цели.
Пресет, который не лучше, чем без обхода, не выбирается.

В аргументах пресета `{ports}`, `{hostlist}` и `{engineDir}`: обработка сужена до сервиса,
fake-файлы берутся из скачанного релиза. `tropa-probe --plan` показывает план без запуска движка.

## Fetcher и EngineHost

`engine.json` (рядом с CLI) закрепляет версию zapret, SHA-256 архива (как его показывает GitHub)
и SHA-256 `binaries/windows-x86_64/winws.exe` из авторского `sha256sum.txt`. Хеши лежат в репозитории,
а не берутся с сервера при скачивании, иначе подмена прошла бы вместе с хешем. Пустые поля — отказ до сети.
Новая версия zapret = правка этих трёх полей.
Зеркала пробуются по очереди. Архив ограничен по размеру и в сжатом, и в распакованном виде.
`../` в именах отвергается. Распаковка идёт во временную папку и переименовывается целиком
в `%ProgramData%\Tropa\engine\<версия>`; маркер с хешем позволяет не качать повторно.

`WinwsEngineHost` пишет hostlist во временный файл, запускает `winws.exe` и ждёт строку готовности
(`capture is started`, настраивается). Если процесс упал или промолчал, бросает исключение с выводом winws.
При остановке убивает дерево процессов и удаляет hostlist. Проект `Tropa.Engine` собран под `net8.0`:
в нём нет Windows API, поэтому кроссплатформенные тесты гоняют его против фейкового winws
(SelfTest, запущенный с `--fake-winws`).

`tropa-probe --tune` от администратора: проверяет, что чужой winws не запущен, ставит движок,
подбирает стратегии и пишет `%ProgramData%\Tropa\profile.json`.

Строка готовности (`windivert initialized. capture is started.`) и имена опций и режимов из пресетов
сверены с исходниками v72.13 (`nfq/nfqws.c`, `nfq/desync.c`); на живом трафике пресеты ещё не гонялись.

## Что обходим и чем

Проверяем несколько хостов на сервис, а обходим все его домены: `targets.json` → `domains`
(и `ports` для нестандартных TCP-портов, у Discord медиа на 2053/8443 и др.). winws обходит домен
со всеми поддоменами. Первый живой прогон показал, зачем это нужно: с тремя проверяемыми хостами
в hostlist приложение Discord висело на «Starting…», потому что обновления оно берёт с `dl.discordapp.net`.

Стратегии в `presets.json` — полевые варианты из `general*.bat` проекта Flowseal/zapret-discord-youtube
(MIT): `multisplit` с `split-seqovl` и шаблоном ClientHello, fake с `fooling=ts|badseq`, `hostfakesplit`.
Для YouTube отдельный набор (`services: ["youtube"]`, `--ip-id=zero`, шаблон google). Fake-файлы только
из официального релиза; тест следит, чтобы не просочились файлы Flowseal.

`companions` — профили, которые пробник не меряет, но приложению они нужны: QUIC для YouTube, голос
Discord по UDP (`--filter-l7=discord,stun`). Включаются под защитой вместе со стратегией сервиса;
если winws их не принял, защита стартует без них, а служба об этом пишет.

Окно сверяет `StatusReport.Build` (отпечаток сборки ядра) со своим и при расхождении обновляет службу
перед подбором тем же запросом UAC.

## Шаблоны Flowseal, свои приложения, обновления

`engine.json` → `extras`: шаблоны ClientHello Flowseal (`tls_clienthello_4pda_to.bin`, `max_ru`,
`ACTIVE_DISCORD_UDP.bin`, `ACTIVE_GAME_UDP.bin`) с закреплёнными хешами, в `files/extra`. Живой прогон
показал, что шаблон не взаимозаменяем: `seqovl=568` с `vk_com` не работал вовсе, с `4pda_to` работает.
Подбор в службе — три прогона на пресет (стратегия, прошедшая дважды, сыпалась на `dl.discordapp.net`).

Свои приложения (`Control/UserApps`, `%ProgramData%\Tropa\apps.json`): название, домены, хосты для проверки
(`host` или `host:port`), игровые UDP/TCP-порты, «обходить всегда». По каналу приходят только данные,
`UserApps.Normalize` проверяет каждое поле; игровые порты служба сама превращает в профили winws по образцу
game filter Flowseal (`--dpi-desync-any-protocol`, `cutoff`). Встроенный сервис своим не перезаписать.

Автообновление zapret (`Engine/ReleaseResolver`): раз в сутки тег с `github.com/.../releases/latest`
(не API), SHA-256 архива со страницы ассетов, SHA-256 `winws.exe` из `sha256sum.txt` релиза. Это доверие
GitHub по TLS, слабее закреплённого хеша, поэтому первая установка — с закреплённой версии. Новая версия
ставится рядом, защита переключается на неё; не стартовала — откат. Принятая версия пишется в
`engine-current.json`. Выключается в настройках окна.

## Составной подбор и проверки «как у приложения»

Живой прогон: ни одна стратегия не брала Discord целиком (лучшие 3/4, падал `dl.discordapp.net` на адресах
Cloudflare), а клиент висел на загрузке, хотя короткие проверки проходили. Отсюда два механизма.

- **Уточнения.** Если лучшая стратегия сервиса не идеальна, подборщик для каждой упавшей цели ищет свою
  стратегию на одном её хосте, при этом основная работает на остальном — так же, как будет под защитой.
  Затем связка проверяется целиком и принимается, только если она лучше. В профиле это `overrides`
  (хост → пресет), в winws — профиль уточнения раньше основного (winws берёт первый подходящий).
  Если основной нет вовсе, работают только уточнения.
- **Проверки ближе к клиенту.** `webSocket: true` — апгрейд до websocket (HTTP 101) и первое сообщение
  сервера: так проверяется gateway Discord. `minBytes: 65536` на странице `discord.com/app` ловит заморозку
  16 КБ. Сторож гоняет те же проверки, поэтому «приложение висит» теперь видно ему, а не только человеку.

## Важные и второстепенные проверки, переподбор без обрыва

Живой прогон: Discord целиком работал (голос, демонстрация, камера), а `dl.discordapp.net` через 5–10 минут
начинал падать. Сторож считал это поломкой и через две проверки переподбирал, а подбор останавливал всю защиту.

- `optional: true` + `role` в `targets.json`: провал такой цели не делает сервис сломанным (окно: «работает,
  кроме: обновления клиента», янтарный крестик), не засчитывается сторожу и не мешает подбору считать сервис
  починенным (`TuneScore`: Ok/Total по важным, второстепенные — только в Progress). Подборщик всё равно ищет
  для неё уточнение.
- Переподбор части сервисов (`TuneAsync(services)`, в том числе сторожем) идёт фоном к стратегиям остальных:
  они работают и во время диагноза, и в каждой попытке (`Tuner.TuneAsync(..., background)`).

## «Почему не открывается?», темы, уведомления

- `Control/SiteCheck`: человек вставляет любой адрес (ссылку, кириллический домен), пробник идёт по этапам
  с запасом 64 КБ, а `Classify` говорит, кто виноват: `Fixable` (режут по имени, заморозка, заглушка) —
  кнопка «Обходить <домен>» заводит своё приложение и подбирает только его; `AddressBlocked` — нужен VPN;
  `DnsSpoofed` — сменить DNS; `SiteRefuses` (403/451 от самого сайта) — блокировка со стороны сайта.
  Проверка идёт из окна, но через системный winws, так что видно и действие текущей защиты.
- Темы: `Themes/Light.xaml` и `Dark.xaml` с одинаковыми ключами; `ThemeManager` перекрашивает общие кисти
  (одна кисть на ключ на всё приложение), «как в Windows» следует за `AppsUseLightTheme`.
- Уведомления у часов, когда окно не на глазах: переподбор сторожем, обновление zapret, защита не запустилась.

## Установщик, обновления, отчёты, релизы

- **Установщик** `Tropa.Setup` (WPF на .NET Framework 4.8 — он есть в любой Windows 10/11, поэтому
  установщик не тащит второй .NET и весит как сама программа; процесс только 64-битный, иначе Windows
  подсунет `Program Files (x86)`). Требует права администратора манифестом. Внутри `payload.zip`:
  самодостаточные окно и служба. Ставит в `Program Files\Tropa`, регистрирует службу её же `install`,
  ярлыки, автозапуск, запись в «Приложения и возможности» (`/uninstall` — удаление, перезапуском из TEMP).
  Окно запускает обычным пользователем через проводник. Журнал: `%TEMP%\Tropa-Setup.log`.
- **Окну права администратора не нужны** и намеренно не требуются: всё привилегированное делает служба,
  а программы с `requireAdministrator` Windows не запускает при входе (сломался бы автозапуск) и каждый раз
  спрашивала бы UAC.
- **Обновления Тропы**: окно раз в 12 часов смотрит `github.com/xckrt/Tropa/releases/latest`, SHA-256
  установщика берёт со страницы ассетов, скачивает, сверяет и запускает установщик с `/update`.
- **Отчёты об ошибках**: необработанные исключения окна сохраняются в `%LocalAppData%\Tropa\crashes`;
  при следующем запуске окно предлагает отправить отчёт — черновиком issue на GitHub, который человек видит
  целиком. Ничего не уходит молча, токенов в коде нет.
- **Релизы**: тег `v1.2.3` → `.github/workflows/release.yml` → тесты, `build/publish.ps1`, релиз
  с `Tropa-Setup-1.2.3.exe` и `.sha256`. Версия одна на всё — `Directory.Build.props`.

## Служба и канал

Логика службы живёт в Core (`Control/TropaController`) и тестируется без Windows. `Tropa.Service` только
обёртка: ServiceBase, ACL канала, скачивание движка, журнал `%ProgramData%\Tropa\service.log`.

- **Защита** — один winws на все сервисы: общий `--wf-tcp` с объединёнными портами, затем профиль
  каждого сервиса со своим hostlist и стратегией, разделённые `--new` (`EngineLaunch.Compose`).
- **Подбор** останавливает защиту (диагноз нужен без обхода), подбирает, обновляет `profile.json`
  и включает защиту снова, в том числе если подбор провалился: человек не остаётся без старого обхода.
- **Сторож** раз в 10 минут: упавший winws перезапускает; сервис, который под защитой лежит две проверки
  подряд, переподбирает (только его). Без сети проверки не засчитываются.
- Тяжёлые операции идут по одной; вторая получает отказ, а не встаёт в очередь.
- Желание «защита включена» хранится в `settings.json` и переживает перезагрузку.

Канал `\.\pipe	ropa`: одна строка JSON на сообщение. Запросы `status`, `check`, `tune {services?}`,
`protect {on}`, события `status`, `probe`, `attempt`. Читать и писать может любой вошедший пользователь,
создавать экземпляры канала только служба; первый экземпляр создаётся с `FirstPipeInstance`, так что
служба не будет работать на канале, который кто-то занял раньше. По каналу приходят только имена
сервисов и действия: аргументы winws и пути берутся из файлов рядом со службой.

Установку делает окно: «Подобрать обход» без службы запускает `Tropa.Service.exe install` с запросом UAC.
Установщик копирует программу в `Program Files\Tropa` (туда без прав администратора не записать,
так что exe службы от SYSTEM не подменить), регистрирует путь в кавычках, включает перезапуск при сбое
и стартует службу; повторный запуск обновляет установку. Ошибки пишутся в `%ProgramData%\Tropa\install.log`,
окно показывает из него причину. Те же команды есть и вручную: `install`, `uninstall`, `run` (в консоли).

Известное: окно не проверяет, что на том конце канала именно служба Тропы
(можно сверить процесс сервера через `GetNamedPipeServerProcessId`).

## Безопасность и площадка

- **Никаких бинарей в репозитории.** `winws` и WinDivert качает Fetcher из релизов
  bol-van/zapret со сверкой хеша. Репо — чистый код, нечему детектиться антивирусом.
- **Зеркала:** GitHub + Codeberg. Fetcher и автообновление умеют несколько источников.
- **Подписанные релизы и воспроизводимая сборка** (`dotnet publish` в CI, хеши в релизе).
- **Нейтральная подача:** «диагностика сети и настройка DPI-обработки».

## Известные дыры Prober

- Только TCP/TLS. **QUIC (YouTube) и UDP-голос Discord не проверяются.** Это нужно
  до Tuner: голос в Discord — половина жалоб.
- Нет сверки DNS с DoH: ловится только явная подмена (0.0.0.0, приватные адреса),
  а не подмена на публичный IP заглушки.
- HTTP/1.1 с `Connection: close`. Для диагностики достаточно, браузер ходит иначе,
  но DPI смотрит на ClientHello и объём, а не на версию HTTP.
