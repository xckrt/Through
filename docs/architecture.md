# Tropa: архитектура

Цель: человек ставит программу, нажимает одну кнопку, и YouTube с Discord работают.
Дальше программа сама замечает, что провайдер что-то поменял, и чинит.
Без батников, без «попробуй general_alt3».

## Компоненты

```
┌──────────────────────┐   named pipe    ┌─────────────────────────────┐
│  Tropa.Tray (WPF)    │ ◄─────────────► │  Tropa.Service (LocalSystem)│
│  иконка, статус,     │   JSON-RPC      │                             │
│  кнопки, уведомления │                 │  Watchdog ──► Prober        │
└──────────────────────┘                 │      │          ▲           │
                                         │      ▼          │           │
                                         │  Tuner ─────────┘           │
                                         │      │                      │
                                         │      ▼                      │
                                         │  EngineHost ──► winws.exe   │
                                         │  Fetcher (релизы bol-van)   │
                                         └─────────────────────────────┘
                     Tropa.Core: Prober, Tuner, модели — без Windows-зависимостей
```

| Модуль | Что делает | Статус |
|---|---|---|
| **Prober** | Проверяет сервис по этапам DNS → TCP → TLS → HTTP → передача и называет способ блокировки | ✅ готов, 12 тестов |
| **Tuner** | Перебирает стратегии `winws`, на каждой гоняет Prober, выбирает лучшую на сервис | следующий |
| **EngineHost** | Запуск и остановка `winws.exe` с нужными аргументами, сбор его stderr | |
| **Fetcher** | Скачивает zapret из официальных релизов, сверяет SHA-256 | |
| **Watchdog** | Раз в N минут лёгкий Prober; при деградации запускает Tuner | |
| **Service** | Windows-служба: держит всё выше, переживает перезагрузку | |
| **Tray** | UI. Без прав администратора, только говорит со службой | |

## Почему Prober устроен по этапам

«Не открывается» ничего не говорит. Этап и способ провала сразу сужают поиск стратегии:

| Что видим | Что это значит | Что пробовать |
|---|---|---|
| `DnsBogus` | провайдер подменяет DNS | DoH/DoT, а не winws |
| `TcpTimeout` / `TcpRefused` | блок по IP | winws не поможет, нужен туннель |
| `TlsReset` | RST сразу после ClientHello, фильтр по SNI | `fake`, `split`, `disorder` по SNI |
| `TlsTimeout` | ClientHello дропается молча | то же, плюс `fake` с низким TTL |
| `TransferStalled` в окне 8–32 КБ | «заморозка 16 КБ» ТСПУ | `fake` + десинхронизация на весь поток |
| `Slow` | шейпинг | стратегии против замедления (googlevideo) |
| `HttpBlockPage` | заглушка (451 / редирект) | DoH + десинхронизация |

Отсюда главная фишка Tuner: он перебирает не все 40 пресетов вслепую, а сначала те, что лечат
конкретный диагноз. Это быстрее и честнее объяснимо пользователю.

## Tuner (следующий шаг)

```
diagnose(services)            → Failure для каждого сервиса без обхода
candidates = presets.Where(p => p.Treats(failure)).OrderBy(p => p.Cost)
for each candidate:
    EngineHost.Start(candidate)
    score = Prober по всем целям сервиса (2 прогона, берём худший)
    EngineHost.Stop()
    if all Ok: break early
save best per service → profile.json
```

Пресеты лежат в JSON рядом с каталогом целей, их можно обновлять без релиза программы.
Перебор идёт на изолированном `--wf-tcp`/`--hostlist` под конкретный сервис, чтобы не ломать
остальную сеть во время подбора.

## Безопасность и площадка

- **Никаких бинарей в репозитории.** `winws` и WinDivert качает Fetcher из релизов
  bol-van/zapret со сверкой хеша. Репо — чистый код, нечему детектиться антивирусом.
- **Зеркала:** GitHub + Codeberg. Fetcher и автообновление умеют несколько источников.
- **Подписанные релизы и воспроизводимая сборка** (`dotnet publish` в CI, хеши в релизе).
- **Нейтральная подача:** «диагностика сети и настройка DPI-обработки».

## Известные дыры Prober

- Только TCP/TLS. **QUIC (YouTube) и UDP-голос Discord не проверяются.** Это нужно
  до Tuner: голос в Discord — половина жалоб.
- Нет сверки DNS с DoH: ловится только явная подмена (0.0.0.0, приватные адреса),
  а не подмена на публичный IP заглушки.
- HTTP/1.1 с `Connection: close`. Для диагностики достаточно, браузер ходит иначе,
  но DPI смотрит на ClientHello и объём, а не на версию HTTP.
