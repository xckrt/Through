# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Tropa is a Windows tool for network-reachability diagnosis and automatic DPI-bypass tuning (it will drive bol-van/zapret's `winws.exe`). Right now only the core exists: a **prober** that checks a service stage by stage (DNS → TCP → TLS → HTTP → transfer) and names *how* the connection is being blocked (SNI RST, silent drop, the ~16 KB "TSPU freeze", DNS spoofing, throttling). The full plan (Tuner, EngineHost, Fetcher, Watchdog, Service, Tray) is in `docs/architecture.md`. Read it before starting a new module.

## Commands

Requires the .NET 8 SDK. Run from the repo root:

```
dotnet build
dotnet run --project tests/Tropa.SelfTest                      # all tests
dotnet run --project src/Tropa.Cli -- --only youtube,discord   # real probe (needs internet)
dotnet run --project src/Tropa.Cli -- --json --targets path/to/targets.json
dotnet run --project src/Tropa.Tray                            # WPF window, auto-runs a check on open
```

- Tests are **not** xUnit/NUnit. `tests/Tropa.SelfTest/Program.cs` is a plain console runner over a `List<(name, Func<Task>)>`, and Tuner/engine/service tests are appended from `TunerTests.All(opts)`, `EngineTests.All()` and `ControlTests.All()`. `FakeEngineHost.PresetFor(host)` mimics winws per-hostlist profiles. It exits 1 on any failure. `dotnet test` does nothing useful and there is no filter flag, so to run one test, temporarily narrow the list. Add a test by appending a tuple to that list.
- CLI exit codes: 0 if every target is OK, 1 otherwise, 2 for a bad argument. The built binary is `tropa-probe`.

## Architecture

- **`Tropa.Core`**: platform-neutral, no Windows dependencies (Prober, Tuner, models). Keep Windows-only code (service, WinDivert/winws hosting, WPF tray) out of it.
  - `ServiceProber.ProbeAsync` runs one target through the stages via a private `Run` helper that tracks the current stage and timings. Each stage maps exceptions/timeouts to a `Failure` with `run.Fail(...)`. A result is a `ProbeResult` with `Verdict` (Ok/Throttled/Blocked/Inconclusive) + `Failure` + `FailedAt` stage + a human-readable `Detail`.
  - A transfer that stalls inside `FreezeWindowMin..FreezeWindowMax` (8–32 KB of body) gets tagged as the TSPU "16 КБ" signature in `Detail`. Tests assert on that substring.
  - `ProbeRunner` probes targets in parallel (default 4). If **all** `IsControl` targets fail, every non-OK result is rewritten to `Inconclusive` (no network, so it isn't a block).
  - `TargetCatalog` loads `targets.json`: services → target lists, camelCase, comments and trailing commas allowed. `Select(only)` always adds the control targets. `domains` and `ports` set what gets bypassed, which is wider than what gets probed. `BypassScope(service)` feeds both the Tuner and protection. Keep the domain lists complete: a narrow hostlist leaves real apps half-blocked.
  - `ProbeOptions` holds all the knobs. `Resolver`, `AllowPrivateAddresses` and `ValidateCertificate=false` exist so tests can run against loopback.
  - `ProbeTarget.Optional` (+ `Role`) marks a nice-to-have target, such as a client-updates host. It is excluded from `TuneScore` Ok/Total and from watchdog strikes, and the tray shows it amber (`Health.Partial`, `TrailState.Minor`). Use it rather than letting a flaky secondary host trigger re-tunes.
  - `ProbeTarget.Voice` (`VoiceProbe.cs`) sends Discord voice IP Discovery over UDP to region servers from `latency.discord.media/rtc`, falling back to built-in IPs. Failure is `Failure.UdpBlocked`. It is optional, and `TuneVoiceAsync` (watchdog, at most every 6 h, or `tune.voice`) swaps `group`/`alternative` companions and stores the choice in `TuningProfile.Companions`.
  - `ProbeTarget.WebSocket` sends a websocket upgrade, requires HTTP 101 and then reads `MinBytes` of frames. Use it for long-lived app connections like the Discord gateway. Short HTTP checks passed while the real client hung.
  - When TLS fails (`TlsReset`/`TlsTimeout`), the prober reconnects to the same IP with `ProbeOptions.NeutralSni` (`ya.ru`) and sets `ProbeResult.SniFiltered`: `true` means the filtering is by name, `false` means all TLS to that IP is dead.
  - `Tuning/`: `Tuner` diagnoses without bypass, then for each service tries only the `presets.json` presets whose `Treats` matches the diagnosis, ordered by `Cost`. Each preset is probed twice and the worst result per target counts (`TuneScore`). It stops early when every target is OK and skips services blocked by IP (`PlanStatus.NotTreatable`). The engine is behind `IEngineHost`/`IEngineSession`. No real winws host exists yet; it belongs in a Windows-specific project, not Core. `TuningProfile` is `profile.json`.
  - Partial re-tunes (watchdog or `tune {services}`) pass the other services' launches to `Tuner.TuneAsync(..., background)`, so tuning one service never drops the others' bypass.
  - Composite tuning: when no preset fixes every target, `Tuner.TuneServiceAsync` searches a per-host override for each failing target while the best preset stays active, then re-verifies the combination. Overrides are stored in `ServiceProfile.Overrides` (host → preset), and `PresetId` may be null. Override launches go before the main launch, because winws uses the first matching profile. `FakeEngineHost.PresetFor` mimics that ordering.
  - `Engine/`: `EngineManifest` (`engine.json`: version, pinned zip sha256 plus `winwsSha256` from the release's `sha256sum.txt`, mirror URLs) and `EngineFetcher` (download → verify hash → zip-bomb and `../` checks → atomic extract under `%ProgramData%\Tropa\engine\<version>`). It fails closed while the manifest is empty.
  - `Control/`: `TropaController` holds all service logic: check, tune, protection on/off, and the watchdog (`WatchdogTickAsync`). Only one heavy operation runs at a time, and a second one is rejected. State lives in `profile.json` and `settings.json` under `DataDir`. `ControlServer` and `ControlClient` speak line-delimited JSON (`Envelope`) over a named pipe (`ControlProtocol.PipeName = "tropa"`). Methods: `status`, `check`, `tune`, `protect`. Events: `status`, `probe`, `attempt`. The pipe accepts only service names and actions, never winws args or paths. `IEngineHost.StartAsync` takes a list of launches. `EngineLaunch.Compose` merges them into one winws command line: a shared `--wf-*` list followed by per-service profiles separated by `--new`.
  - "Выбрать запущенную программу" (Apps page, `MainViewModel.Observe.cs`): the tray lists windowed processes, and `apps.observe {process, seconds}` makes the service run an ETW session (`Tropa.Service/EtwAppObserver`, NuGet TraceEvent) with DNS-Client and Kernel-Network for those PIDs. `Core/Control/AppSuggester` turns the result into an `AppDefinition`: registrable domains without OS noise, ports as ranges, never 80/443. It goes through `UserApps.Normalize` like manual input. Only a process name crosses the pipe. Port byte order is decided from the data (are 443/80/53 seen raw or swapped). Debug with `Tropa.Service.exe observe <name> <sec>` (needs admin).
  - Network profiles: `ControllerOptions.Network` identifies the current network. The service's `WindowsNetworkIdentity` uses the gateway MAC via SendARP, with the name from NetworkList\Signatures; `Tropa.Service.exe network` prints it. Each network has its own `networks/<key>.json` profile. The first identified network migrates the old `profile.json`, and a new network gets a copy of the previous profile and a check. `NetworkChangedAsync` runs on `NetworkAddressChanged` (5 s debounce) and on every watchdog tick, and skips while busy.
  - `Doh/`: secure DNS. `SecureDnsServer` answers UDP+TCP on 127.0.0.1/::1:53 through DoH. Upstreams are reached by IP only (1.1.1.1, 8.8.8.8, 9.9.9.9 over HTTP/2), because system DNS points at us and a hostname would loop. Answers are cached by min TTL (max 5 min), and a working upstream moves to the front. The controller switches adapters only after `SelfTestAsync` (which bypasses the cache) succeeds. The watchdog fails open: after two failed self-tests it restores the old DNS and switches back when DoH recovers. `IDnsSwitch` is implemented in the service by `WindowsDnsSwitch` (netsh, originals saved in `dns-restore.json`, restored on stop, on start when disabled, and on uninstall). `tropa-probe --dns` checks it live.
  - `Telegram/`: local MTProto proxy, a C# port of Flowseal/tg-ws-proxy (MIT). `TelegramProxy` listens on 127.0.0.1 (port from `settings.json`, default 1443, next free one if busy), decodes the client's obfuscated init with the dd-secret, and bridges to Telegram with re-encryption: pooled WebSocket to `kws{dc}.web.telegram.org` via 149.154.167.220 (DC2/4 only) → Cloudflare domains → direct TCP. `TelegramProbe` sends `req_pq_multi` through the proxy and expects `resPQ`. It is the self-check (`telegram.check`, also run by the watchdog), and `MarkSelfCheck` keeps it out of the stats. The controller runs the proxy outside `_busy`, so tuning never touches it. `tropa-probe --telegram` checks all DCs live. Tests use a loopback fake DC (`TelegramTests.FakeDc`).
- **`Tropa.Service`** (`net8.0-windows`, NuGet `System.ServiceProcess.ServiceController`): a thin wrapper. `Installer.cs` copies the app to `Program Files\Tropa`, because a SYSTEM service must not run from a user-writable folder. It registers a quoted binPath and starts the service. Rerunning it upgrades the install. Errors go to `install.log`. Tray references this project so `Tropa.Service.exe` sits next to `Tropa.exe`. "Подобрать обход" with no service running launches `install` with `Verb=runas`, so the user never touches admin steps or JSON. The pipe ACL lets authenticated users read and write, and the first instance is created with `FirstPipeInstance`. A `NoForeignWinws` guard refuses to start next to someone else's winws. The log goes to `%ProgramData%\Tropa\service.log`.
  - `Control/UserApps.cs`: user-added apps (`apps.json`). Everything arriving over the pipe goes through `Normalize`, a strict validator, and game ports become companion profiles built from a fixed template. Never accept winws args or paths from the client. `Engine/ReleaseResolver.cs` finds the latest bol-van release by scraping github.com (api.github.com is blocked for some ISPs). `TropaController.UpdateEngineAsync` swaps engines and rolls back if the new one fails to start.
- **`Tropa.Engine`** (`net8.0` on purpose, so cross-platform tests can reference it): `WinwsEngineHost` writes a temp hostlist, starts winws, and waits for `ReadyMarker` on stdout or stderr. On dispose it kills the process tree. Tests point `ExecutablePath` at the SelfTest binary itself with `--fake-winws ready|crash|silent`, which `EngineTests.FakeWinwsAsync` handles at the top of `Program.cs`.
  - `presets.json`: field strategies taken from Flowseal general*.bat. `services` scopes a preset (YouTube has its own set). `companions` hold untuned UDP profiles (QUIC, Discord voice) that are added under protection, and protection retries without them if winws rejects them. Reference only fake files that exist in the official release (a test enforces this). `TropaBuild.Id` is sent in `StatusReport.Build`, and the tray reinstalls an outdated service.
- **`Tropa.Cli`**: thin arg parsing + text/JSON output over Core. `--plan` prints the Tuner's candidate list without starting an engine. `--tune` lives in `TuneCommand.cs`. It needs admin and refuses if a `winws` process is already running. `targets.json`, `presets.json` and `engine.json` are copied to the output directory and can be edited without rebuilding. SelfTest links `presets.json` and validates it.
- **`Tropa.Tray`** (WPF, `net8.0-windows`, binary `Tropa.exe`). On open, `MainViewModel.StartAsync` tries the service pipe for 400 ms. If the service answers, all actions (check, tune, protect) go through `ControlClient`, and pipe events are marshalled to the UI thread. If not, the window probes in-process and offers only diagnostics. Both modes render from `TargetReport`/`ServiceReport`. The constructor takes `ProbeOptions`, a data directory and a pipe name, so it can run against fake servers and an in-process controller. `ProbeRunner`'s `IProgress<ProbeResult>` lets rows fill in as results arrive. `TrailView` is the custom-drawn five-stage "trail" (DNS → TCP → TLS → HTTP → передача) that breaks at the failing stage. Its node centres line up with the stage labels through the shared `NameColumn`/`TrailColumn` widths in `App.xaml`. All colours and fonts are resources in `App.xaml`, and the plain-language failure text is in `Wording.cs`. There are no UI tests.
  - Overview (`MainViewModel.Home.cs`) is two cards, "Обход блокировок" and "Telegram". Each has a `PowerOrb` (custom animated Button: dashed trail ring that spins, ripples while on, colours from theme brushes, still when Windows animations are off) and plain-language status. One click either toggles protection or tunes when nothing is tuned yet. Service health shows only as chips. The per-stage trail view moved to `Pages.Diagnostics` ("Подробная проверка"), which is not in the nav. The tray menu has both toggles.
  - The Tray UI is split into `MainViewModel` (overview, service connection) and `MainViewModel.Pages.cs` (navigation, apps page and form, log, settings, title-bar pill). The window uses `WindowChrome` with a custom caption, so caption controls need `WindowChrome.IsHitTestVisibleInChrome`. Theme colours live in `Themes/Light.xaml` and `Themes/Dark.xaml`. Reference them only as `{DynamicResource Paper|Ink|…}`. `ThemeManager.Apply` recolours shared top-level brushes, because swapping the merged dictionary did not reach existing elements. The overview's "Почему не открывается?" box is `MainViewModel.Site.cs` over `Core/Control/SiteCheck`. When hosting `App` without `Run()` (offscreen screenshots), clear `Application._startupUri`, otherwise a second real `MainWindow` with a tray icon and pipe connection appears on the user's desktop. `IconArt.cs` draws the brand mark (trail blaze on a plate with a dashed trail) for each size. Regenerate `tropa.ico` with `IconArt.SaveIco` rather than editing it by hand. `TrayIcon.cs` uses WinForms `NotifyIcon`; WinForms global usings are removed in the csproj to avoid clashes with WPF.
- **`Tropa.SelfTest`**: `TunerTests.cs` uses `FakeEngineHost`. While a preset is "running", `FakeServer.SniFilter(..., bypassed: engine.AllowConnection)` lets connections through when `passes(presetId, connectionNo)` returns true, which also covers flaky presets. `FakeServer` stands up a local TLS server that mimics each blocking behavior (RST after ClientHello, silence, a stalled body, a 451 or block-page redirect). Each test checks that the prober reports the expected `Verdict/Failure/Stage`. No internet needed.

The `Failure` → strategy mapping table in `docs/architecture.md` drives the design: Tuner tries the `winws` presets that treat the diagnosed failure first, instead of brute-forcing all of them. When you add a `Failure` value, update that table and the `treats` lists in `presets.json`.

## Release & install

- The version lives in `Directory.Build.props` (`TropaBuild.Version`). To ship: push tag `v1.2.3`, and `.github/workflows/release.yml` runs the tests, then `build/publish.ps1`, then creates the GitHub release with `Tropa-Setup-1.2.3.exe` + `.sha256`. The tray's update check expects exactly that asset name.
- `Tropa.Setup` targets **net48** on purpose (no bundled runtime, so the installer stays small). It needs `Prefer32Bit=false`, the `IsExternalInit` polyfill, and explicit `using`s; there are no implicit usings there. The payload is `artifacts/payload.zip`, embedded only when it exists.
- The window intentionally runs asInvoker. Elevation happens only in the installer (manifest) and via the service.
- Crash/bug reports are never sent silently. `CrashReports.OpenIssue` opens a prefilled GitHub issue and copies the full text to the clipboard.

## Conventions

- Code comments, XML docs, CLI output and `Detail` strings are in **Russian**. Keep it that way.
- No binaries in the repo. `winws`/WinDivert must be downloaded at runtime from official zapret releases with SHA-256 verification (the planned Fetcher).
- Known Prober gaps (in the docs): no QUIC/UDP (YouTube QUIC, Discord voice), DNS spoofing is caught only for obvious bogus addresses (no DoH cross-check), and HTTP is HTTP/1.1 with `Connection: close`.
- If a build suddenly fails with missing `Microsoft.NETCore.App.Ref` files or "could not resolve SDK", a Visual Studio/.NET installer is usually running. Wait for it to finish, or run `dotnet restore --force` (it fetches the targeting pack from NuGet).
- Locally only the .NET 10 SDK may be installed, and its WPF markup compiler fails on the net48 `Tropa.Setup` (MC1000 "System.Private.CoreLib"). CI pins 8.0.x. Build the other projects one by one, or install the .NET 8 SDK.
- Windows quirk: connecting to a closed loopback port takes ~2 s (Windows retries the SYN after RST), so test `ConnectTimeout` is 5 s.
